# 제출 환경 패킷 리플레이 검증

## 경로

실제 protocol `PlaneInfo` 구조를 사용해 다음 경로를 재생했다.

`PlaneInfo → plane_info_to_state → Tactical16 → rear120 Gate → BT → RL residual → CMD`

## 결과

- Gate ON 6 frame: BT 6회, RL 1회(action repeat 6), CMD index 연속.
- final throttle은 모든 frame에서 BT throttle과 같다.
- beam negative 60 frame: BT 60회, RL 0회, final action이 BT와 정확히 같다.
- 관측은 매 frame 16개 float32 feature로 생성됐다.
- RL 예외·NaN/Inf·timeout은 해당 frame BT fallback으로 검증했다.

## 판단

packet-to-command 의미는 학습 residual composition 계약과 일치한다. 실제 BT DLL과 선택된 bundle을 넣은 replay는 후보 동결 후 반복해야 한다.

## 자기 반박

현재 replay provider는 결정론적 test double이다. 실제 DLL의 stateful tick과 RLlib 추론 초기화 비용은 반영하지 않는다.
