# 0815 하이브리드 기준선 분석

## 현재 상태

- 기준 `main`: `f443cca9a9ab4e0f79c3f5f61378bb944cede56e`
- 작업 브랜치: `codex/0815-hybrid-aim-training`
- 외부 0815/AIP2/AIP3 파일은 저장소에 복사하지 않았다.
- 해시와 크기는 `automation/manifests/0815_hybrid_baseline_manifest.json`에 기록했다.

## 현재 Hybrid 구조

기존 `HybridActionProvider` 중 `offensive_residual` 모드는 BT를 매 프레임 실행하고 Gate가 활성화된 경우에만 RL을 추론한다. 조종면은 `BT + scale × RL action`으로 더하고, throttle은 convex blend를 사용한다. Gate OFF에서는 RL을 호출하지 않고 clipping된 BT action을 반환한다.

현재 최적 설정 파일은 residual `0.10`, RL 6-frame repeat, Offensive Gate `152.4–1500 m`, ownship ATA `15°` 이하, target ATA `135°` 이상을 사용한다. 이 결과는 기존 Pure RL bundle을 추론 시점에 섞은 것이므로 이번 조준 보정 residual policy의 성공 근거가 아니다.

## 현재 학습 구조

`train_rllib.py`와 `train_curriculum.py`는 `ownship_control_mode="rl"`로 환경을 생성한다. 환경의 `step(action)`은 RL 4D action을 roll/pitch/yaw/throttle 전체 조종 명령으로 변환해 JSBSim에 적용한다. 0815 BT action을 먼저 구한 뒤 residual을 적용하는 학습 경로는 없다.

따라서 현재 학습은 **Pure RL 전체 조종**이며, 현재 Hybrid는 **inference-only 결합**이다. 이번 요구사항을 만족하려면 BT-in-the-loop residual 학습 환경이 필수다.

## 발견된 실행 계약 문제

0815 DLL은 cwd의 `Rule_DCS_GDCC_0815.xml`을 하드코딩하지만, 현재 rule manager는 지정 XML을 `Rule_forTraining.xml`로만 활성화한다. 따라서 별도 alias 없이는 0815 `CreateBehaviorTree` 초기화가 실패한다. AIP3 소스는 파일명과 달리 `Rule_sei_AIP2_default.xml`을 하드코딩한다. 세 XML의 내용과 SHA256은 모두 동일하지만, 재현 가능한 로더는 DLL별 필요 alias를 명시적으로 관리해야 한다.
