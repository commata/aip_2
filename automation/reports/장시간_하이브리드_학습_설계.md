# 장시간 하이브리드 학습 설계

## 목적과 상태

최종 Target BT가 없는 상태에서 0815 조준 residual policy가 한 scripted target에 과적합하지 않도록 proxy curriculum을 사용한다. 이 단계의 최대 상태는 `PROXY_TARGET_VALIDATED`이며 최종 Target에 대해서는 `TARGET_BT_PENDING`을 유지한다.

## 후보 선정

- observation: `aim_residual10_v2`
- Gate: Phase-aware Aim Gate A (`PROVISIONAL`)
- residual scale: `0.125`
- composition: `saturation_aware`
- residual axes: roll/pitch/yaw
- throttle: Pure 0815 BT command 그대로
- RL action repeat: 6 simulator frame
- algorithm: SAC

13D BT-aware는 두 training seed에서 action saturation을 낮췄지만 vertical/crossing 일반화 개선이 재현되지 않아 장시간 후보로 승격하지 않았다. 10D를 최종 정답으로 보는 것이 아니라, 현재 Pareto 비교에서 더 단순하며 설명 가능한 후보로 선택했다.

## Episode-level Proxy Curriculum

| profile | weight | 역할 | 학습 사용 |
|---|---:|---|---|
| `autopilot_crossing` | 2 | dense aim signal과 좌우/상하 mirror | 사용 |
| `bt_0815` | 1 | 0815 family self-play | 사용 |
| `bt_aip2` | 1 | 별도 pursuit behavior cluster | 사용 |
| `bt_aip3` | - | 0815와 동일한 관측 행동 cluster | held-out 보존 |

Target identity는 observation에 넣지 않는다. 환경은 episode reset마다 seed된 RNG로 profile을 선택하고 telemetry/custom metric에만 profile ID를 기록한다. BT profile을 바꿀 때 이전 native BT를 `RemoveBT`한 뒤 선택된 DLL의 provider를 활성화한다.

세 BT XML의 SHA256은 모두 `D84C27B0B8BA22E1649AF2375BE0B83C762BC62EB5047BB590539B374F8271EE`이므로, one source XML을 DLL별 hard-coded alias에 활성화한다. DLL hash는 target profile manifest의 검증값을 사용한다.

## 유효 learner time 정의

각 `algorithm.train()` 호출에서 다음 두 값이 모두 이전보다 증가한 경우에만 그 호출의 monotonic wall time을 누적한다.

1. `num_env_steps_sampled_lifetime`
2. `num_env_steps_trained_lifetime` 또는 `num_module_steps_trained_lifetime`

Ray 초기화, algorithm build, checkpoint 저장, validation, 대기 시간은 포함하지 않는다. progress CSV에는 `sampled_steps`, `learner_steps`, `train_call_wall_s`, `effective_learner_time_s`를 기록한다.

## 단계

1. 5 iteration native smoke
2. 유효 learner 1,800초 pilot
3. 동일 seed/scenario paired development validation
4. 설정 동결
5. 독립 seed 2개, 각 유효 learner 18,000초 목표
6. config freeze 후 AIP3/새 geometry 독립 재검증
7. 200초 proxy full-fight

장시간 run은 높은 iteration 상한과 유효 learner-time 종료 조건을 함께 사용한다. 시간 조건에 먼저 도달하면 정상 종료하여 final bundle/checkpoint/record를 만든다.

## Checkpoint와 보존

- lightweight bundle과 native checkpoint를 주기적으로 모두 저장한다.
- 기존 bundle/checkpoint를 덮어쓰지 않도록 output tag는 seed와 단계를 포함한다.
- simulator가 갱신하는 추적 파일 `aircraft/f16/f16_init.xml`은 experiment parent process가 성공/오류 종료 모두에서 실행 전 byte로 복원한다.
- 대형 artifact는 Git에 추가하지 않고 config, SHA256, progress 요약, 판단만 commit한다.

## 중간 중단 기준

- sampled 또는 learner step 정지
- policy weight/learner loss의 비정상 NaN
- crash 증가
- 한 target profile이 설정 분포와 현저히 다른 실행 빈도를 보임
- target profile 전환에서 DLL/rule alias 오류
- reward만 상승하고 LOS→Cone→Damage chain이 악화

episode가 종료되지 않은 iteration의 RLlib episode aggregate `NaN`은 learner NaN과 구분한다.

## 승격 판단

장시간 완료 자체는 성공이 아니다. 독립 seed 두 개에서 crash regression 없이 mirror/generalization, LOS/LOS-rate, Cone/First Damage, 실제 Damage가 설명 가능한 방향으로 재현되어야 한다. 작은 평균 이득보다 worst-case 기하, saturation/headroom, trajectory 안정성을 먼저 본다.

## 현재 한계

- Gate A active ratio가 near-aim validation에서 약 86%로 넓다.
- BT proxy 30초 pilot은 공격 opportunity가 부족했다.
- 최종 Target BT가 없다.
- 실제 서버 정보가 없어 server validation을 아직 수행할 수 없다.
