# 0815 BT-in-the-loop 잔차 학습 설계

## 목표

0815 DLL의 roll/pitch/yaw/throttle 명령을 매 60 Hz simulator frame에서 먼저 구한다. RL은 Gate ON에서만 roll/pitch/yaw residual을 출력하고, throttle residual은 학습·추론 모두에서 0으로 강제한다.

```text
0815 raw BT action
        +
scale × RL residual [roll, pitch, yaw, 0]
        |
      clip
        |
     JSBSim
```

Gate OFF에서는 `Final CMD == raw 0815 BT CMD`를 array equality 및 simulator trajectory paired test로 검증한다. RL action을 계산하는 학습 과정이더라도 Gate OFF 적용 correction은 정확히 0이다.

## 구현 단위

1. `ResidualTrainingActionProvider`를 추가해 policy action을 전체 조종 명령이 아니라 residual로 해석한다.
2. 0815 `BTActionProvider` 원본 throttle 모드를 사용한다.
3. 학습 환경은 BT를 매 simulator frame에서 실행하고 RL action은 환경 step 동안 hold한다.
4. 학습 action space는 호환성을 위해 4D를 유지하되 4번째 throttle residual은 무시하고 telemetry에 위반 요청 크기를 기록한다.
5. residual scale은 config validation에서 `0.10`, `0.125`, `0.15`만 허용한다.

## 초기 Observation

Stage 1은 10D를 사용한다.

1. LOS azimuth
2. LOS elevation
3. LOS azimuth rate
4. LOS elevation rate
5. ATA
6. target ATA
7. distance
8. closing rate
9. ownship speed
10. ownship altitude

모두 정규화한다. 첫 구현에서는 BT action을 observation에 넣지 않고, residual 학습이 안정화된 뒤 3D BT surface command 추가를 ablation한다. Observation 크기를 늘리기 전에 실패 근거를 먼저 확인한다.

## 초기 Reward

초기 reward는 승률보다 조준 안정성을 직접 학습한다.

- LOS 크기 감소
- LOS rate RMS 감소
- phase별 Damage Cone 진입·유지
- 실제 target damage
- residual L2 패널티
- surface clipping/포화 패널티
- 속도·에너지 저하 패널티
- 600 m 이하 저고도 위험 및 crash 패널티

Cone 진입만 반복하는 reward hacking을 막기 위해 dwell은 연속 유지에 가중하고, damage가 따르지 않는 cone reward의 상한을 둔다. Terminal win/loss는 보조 신호로만 사용한다.

## Gate A/B

### Gate A: Aim-near

현재 phase의 반각과 사거리에 pre-aim margin을 더한다. 1차 후보는 phase별 반각에 `+7°`, 사거리에 `+300 m`를 더하고, 이탈은 각 `+3°`, 거리 `+250 m`를 추가한다. 진입 조건이 너무 넓은지 gate active ratio와 gate-on window로 판단한다.

### Gate B: Offensive

기존 baseline을 사용한다.

- 진입: `152.4–1500 m`, ownship ATA `<=15°`, target ATA `>=135°`
- 이탈: `<=2000 m`, ownship ATA `<=25°`, target ATA `>=110°`

두 Gate 모두 진입/이탈 hysteresis, 최소 유지 frame, entry/exit/active duration telemetry를 갖춘다. Gate C는 A/B의 보완 근거가 생긴 경우에만 추가한다.

## Curriculum과 데이터 분리

- Stage 1: 후방 공격 초기 기하, 20–30초
- Stage 2: Gate 진입 직전 공격 기하, 40–60초
- Stage 3: AIP2 및 움직이는 target, scenario variation
- Stage 4: 200초 전체 교전 paired 검증

기존 `307`, `401` 및 과거 scenario는 참고 재현에만 사용한다. 새 development/validation seed와 최종 unseen seed를 별도로 고정한다. Final set을 보고 수정하면 해당 set은 tuning set으로 강등하고 새 unseen set을 만든다.

## 1차 실험

1. Gate OFF action equality unit/integration test
2. Aim Gate/Offensive Gate activation smoke
3. SAC 3–5 iteration 학습 가능성 smoke
4. 동일 scenario/seed에서 raw Pure 0815, Gate A, Gate B paired 평가
5. residual scale `0.10/0.125/0.15` 비교

PPO는 SAC가 작은 continuous residual을 학습하지 못하거나 action 진동이 반복될 때만 짧은 동일 조건 smoke로 비교한다.
